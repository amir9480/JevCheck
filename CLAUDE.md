# CLAUDE.md

JevCheck: an MV3 extension for Chromium, with a Firefox port. Clicking the toolbar icon opens a side panel (Firefox: sidebar) showing the active page as Markdown (Raw / Preview tabs).

## Stack
Vite 8 + `@crxjs/vite-plugin` (root `src/`, config in `vite.config.ts`, manifest in `manifest.config.ts` (`defineManifest`)), TypeScript, React 18, Tailwind v4 (CSS-first, no tailwind.config), shadcn/ui (new-york), pnpm.

## Commands
- `pnpm dev` — Vite dev server with HMR; load `build` unpacked in Chrome
- `pnpm build:chrome` — production build to `build`
- `pnpm dev:firefox` (`scripts/dev-firefox.mjs`: `vite build --watch` + `web-ext run`, auto-reload, no HMR), `pnpm build:firefox` (to `build-firefox`), `pnpm package:firefox`, `pnpm lint:firefox`
- `pnpm exec tsc --noEmit` — typecheck (no test runner configured)
- `pnpm schema` — regenerate `public/schema/question-set.v<N>.json` from the zod schema (`pnpm build` fails via `--check` when it is stale)
- Add shadcn components with the shadcn CLI; `components.json` aliases point at `src/components/ui`.

## Firefox port
`vite --mode firefox` switches `manifest.config.ts` (`sidebar_action`, `background.scripts`, `browser_specific_settings.gecko`, no `sidePanel`) and `vite.config.ts` (crxjs `browser: 'firefox'`, `build-firefox`, sidebar as an explicit input). Code branches on `import.meta.env.MODE === 'firefox'` (static, so each build drops the other branch): `background.ts` uses `chrome.sidebarAction` (`setPanel` per tab, only when the URL differs, since it reloads the sidebar; typed in `types.d.ts`). The Firefox sidebar is per window and shows the active tab's panel; opened without `?tabId` (from Firefox's sidebar menu), `sidebar/scripts.tsx` redirects to the active tab. `permissions.request` must be the first await in a gesture (Firefox drops the gesture at any await), so never check `contains` before it. Keep both builds working.

## Architecture
1. `src/background.ts` — opens the side panel from `action.onClicked` and the context menu. The panel is per tab: the global panel is disabled and every tab gets `sidebar/index.html?tabId=<id>` via `sidePanel.setOptions({tabId})` (re-applied on tab create/activate/update). Selections are handed over in `chrome.storage.session` under `selectionKey(tabId)`.
2. `src/sidebar/sidebar-app.tsx` — on mount calls `extractPage(tabId)`, then follows its own tab (`tabId` from the URL) via `tabs.onUpdated` (a URL change drops the page and its result; no refresh button). Live selection: every `load()` injects `watchSelection` (`lib/selection.ts`, self-contained, one `selectionchange` listener per page, debounced) which returns the current selection and later posts `jevcheck:selection` runtime messages; a selection of 20+ non-space chars replaces the page, clearing it goes back to the whole page. The context menu still works (it also opens the panel and can auto-run a quick-access set). Permission/error states replace the whole body under the top bar. Markdown Raw/Preview lives in `page-markdown-dialog`. Dark mode: `lib/theme.ts` (`.dark` class, localStorage). Deletes go through `useConfirm()` (`confirm-dialog.tsx`, provider in `scripts.tsx`), never `window.confirm`.
3. `src/lib/extract-page.ts` — `chrome.scripting.executeScript` returns `{title, url, html}` from the panel's tab (`activeTab` + `scripting`; no host permissions, no content scripts).
4. `src/lib/clean-html.ts` — DOMParser (inert) strips script/style/template/svg/iframe/nav/footer/hidden nodes/ads/cookie banners/analytics widgets (selector list + class/id token match in `isNoise`)/comments, removes images/media (img, picture, video, audio, etc.), drops unmarked menus by link density (`isLinkMenu`: 3+ short links making up 70%+ of a block's text), unwraps every link to plain text and strips bare URLs outside `pre`/`code` (no attributes survive), prefers `main` (or a lone `article`; several articles keep the body). Never strips `form` (ASP.NET wraps whole pages in one). `cleanHtml(html, {selection: true})` (used for selections) removes only non-text markup (`NON_TEXT_SELECTOR`: scripts, styles, media, form fields) and links/URLs; site chrome (`stripChrome`: nav/footer/menus/ads/cookie banners, noise tokens, link menus, `main` preference) is stripped from whole pages only, so selected footer or menu text reaches the model.
5. `src/lib/html-to-markdown.ts` — Turndown + `turndown-plugin-gfm` (types in `src/types.d.ts`).
7. `src/lib/decision/` — fetch-based decision API client (Vercel `/v1/evaluate`, OpenRouter `/api/alpha/decisions`, OpenAI `/decisions`, TypeSafe `/v1/systemone`, OpenCode `opencode.ai/inference/v1/systemone` (TypeSafe-compatible, free model; `ProviderInfo` has `badge` and `keyUrl`); custom = OpenAI/TypeSafe-compatible). Normalized questions/answers in `types.ts`.
8. `src/lib/key-vault.ts` + `use-keys.ts` — API keys AES-GCM encrypted in `chrome.storage.local`; the non-extractable CryptoKey lives in IndexedDB `JevCheckVault`. Missing/mismatched key wipes all keys.
9. `src/lib/origin-access.ts` — provider hosts are *optional* host permissions, requested when a key is added (which also tests it) and re-requested on Evaluate.
10. Question sets (Dexie `JevCheckDB` v5: `questionSets`, a shared `documents` library referenced by `documentIds`, `evaluations`, `meta`; nothing is seeded). `lib/question-sets.ts` (CRUD + live hooks), `lib/evaluate-set.ts` (builds `{context, documents, page}` state, truncates the page 70/30 from the middle, SHA-256 hash → cached result in `evaluations`), Question types: boolean/choice/score map to Jev natively; `multi` is sent as one boolean per answer (`<qid>_<answerId>`) and the per-question `threshold` (display-only, not in the cache hash) decides which answers are highlighted. `lib/decision/limits.ts` (Jev limits: 32k state+longest question, 64k request, ≤255 choices, 2–10 score levels; UI blocks anything over them), `lib/answer-presets.ts` (ready answers, color palettes), `lib/icon-map.ts` (curated lucide icons), `lib/spreadsheet.ts` (CSV/XLSX → answers).
11. UI: `question-set-picker` + `evaluation-panel` on the main view; `question-set-editor-dialog` (full-screen: name, documents + uploader, context, questions) with `question-editor`, `answers-editor`, `color-picker`, `icon-picker`, `spreadsheet-import-dialog`. Floating UI inside dialogs must be inline or use `PortalContainerContext` (popovers break in the transformed dialog).
12. `src/templates/` — ready-made question sets: one directory per template with a single `index.ts` exporting a `QuestionSetTemplate` (`types.ts`), listed in `templates/index.ts` (`TEMPLATES`). `createFromTemplate()` in `lib/question-sets.ts` instantiates one. `template-picker-dialog` (the + button; last card = empty set) and `onboarding-dialog` (first run only: pick a template, upload documents if it `requireDocuments`, then the provider settings dialog opens if no key exists; gated by `meta.onboarded`, which `db.ts` sets on `ready` for installs that already have sets).
13. Question dependencies: `Question.dependsOn` (`question-types.ts`) hides a question in results unless an *earlier* source question was answered a qualifying way (boolean/choice top answer in `answerIds`, multi any answer at/above its threshold, score >= `minScore`). Display-only, so it is not in the cache hash; the model still answers every question. `lib/dependencies.ts` has `resolveVisibility` (transitive), `sanitizeDependencies` (run on every editor edit; also checked by `validateSet`) and `describeAnswer`. Each saved `Evaluation` stores a `questions` snapshot: History renders with it, while the live result of the current page (`shown.live`) uses the current set. `cloneQuestionSet` remaps rule ids. Templates use `gateQuestion`/`withGate` (`templates/types.ts`). Editor UI: `dependency-editor.tsx` (collapsible "Advanced").
14. Page checks: `lib/page-checks.ts` (`PAGE_CHECKS`) defines hidden boolean questions sent with every evaluation (page or selection): `page_mixed_content` (many unrelated topics) and `page_enough_content` (asked positively, saved inverted: can the set's questions, listed and cut to 150 chars, be answered from the page alone; also fails locally when `Evaluation.contentTokens` < `MIN_CONTENT_TOKENS` = 80, and `supersedes` the mixed-content hint). They are reserved in `budgetOf` and part of the cache hash; probabilities are saved as `Evaluation.mixedContent` / `insufficientContent`, and at >= 0.5 `evaluation-panel` shows one hint per check above the results (`CHECK_HINTS`, page vs selection wording). A new check needs an entry there, an `Evaluation` field and a hint.
15. Share / import: the Clone button opens `share-question-set-dialog` (download `.jevcheck.json`, copy JSON, or clone → editor). `import-question-set-dialog` (a card after "Start from scratch" in the template picker and in onboarding): textarea + paste from clipboard (optional `clipboardRead` permission, requested on click) + open file, validated live, then `importQuestionSet` (fresh ids, free name) opens the editor. Format: `lib/question-set-schema.ts` (zod; source of the JSON Schema), `lib/question-set-config.ts` (`exportConfig` / `parseConfig`, migrations). Exports carry `$comment` (first key: what the file is + where to get the extension), `$schema` (raw GitHub URL of the versioned schema), `format`, `version`; documents, quick access and timestamps are never exported.
6. Preview renders with `react-markdown` + `remark-gfm` + `@tailwindcss/typography`.

## Template and question rules
The model only ever sees the page's **readable text** as Markdown (`clean-html.ts` strips scripts, styles, images and media, nav/footer, hidden nodes, all attributes, link targets and URLs). It cannot judge source code, HTML tags, meta tags, structured data, page speed, images, video, layout, colors, links or URLs. Never write template questions, answers or context that assume otherwise (no "does it have an H1", "are the images good", "internal links", "page speed"); ask only about what the wording itself states. The SEO template is a *content* checkup for that reason.

## Question set config compatibility
Exported configurations live in users' files and must keep importing forever.
- Adding an optional field: keep `CONFIG_VERSION`, run `pnpm schema`. Unknown fields are ignored on import, so older builds still read newer files of the same version.
- Renaming, removing, retyping a field or changing its meaning (also tightening a limit an old file may exceed): bump `CONFIG_VERSION`, add `MIGRATIONS[N]` (N-1 → N) in `question-set-config.ts`, run `pnpm schema` (new `question-set.v<N>.json`). Never delete or edit old schema files or migrations; files with a newer version are rejected with an "update the extension" message.
- A change to `Question`/`AnswerOption`/`QuestionSet` that should travel with a set must also update `question-set-schema.ts` and `exportQuestion`.

## Conventions
- `@/` alias maps to `src/`; use it in new code.
- TypeScript source files are named in kebab-case (`sidebar-app.tsx`, not `SidebarApp.tsx`); use `git mv` when renaming. Component/function identifiers inside stay PascalCase/camelCase.
- Restricted pages (`chrome://`, Web Store, PDFs) make `executeScript` throw; this surfaces as a friendly error in the panel.
- If `activeTab` is not granted on toolbar click in some Chrome version, fall back to `host_permissions: ["<all_urls>"]` and update STORE.md.
